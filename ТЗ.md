# ТЗ: модуль сбора данных о СКЗИ (кейс №03, ГРЧЦ)

Документ для команды. Требования организаторов помечены **[кейс]**, наши собственные решения — **[решение]**, непроверенные допущения — **[проверить]**. Первоисточник: PDF кейса и `Conditions/TASK.md` в репозитории telecom.

## 1. Что делаем

Одно приложение для Windows 10, которое запускается **только на ПК администратора**. Админ указывает компьютеры локальной сети, приложение удалённо собирает с них личные сертификаты и версию КриптоПро CSP, разбирает сертификаты и записывает результат в таблицу MSSQL. На сканируемые ПК ничего не устанавливается (уточнение организаторов после созвона).

## 2. Жёсткие ограничения [кейс]

- C#, .NET Framework 4.5 (не .NET Core / 6 / 8).
- БД — Microsoft SQL Server.
- Результат — `.exe` под Windows 10.
- Файловый лог: все исключения и ошибки, время с миллисекундами, формат строки `16.09.25 08:43:23.739 - текст`.
- Оформление кода: комментарий у каждой функции, осмысленные имена, пробелы вокруг операторов, табуляция для вложенных блоков.

## 3. Функциональные требования

### 3.1. Конфигурационный файл [кейс]

Приложение читает из конфига список директорий для сканирования.

**[решение]** Рабочий XML `scan.config.xml` и список ПК `computers.xml` находятся в папке `configs` рядом с `Telecom.sln` при запуске сборки из репозитория и рядом с `.exe` в отдельной поставке. При первом запуске рабочий XML создаётся из поставляемого шаблона. Файл списка ПК создаётся при первом сохранении списка. В XML указывается строка подключения к БД. Пути задаются от корня диска сканируемого ПК и допускают `*` вместо имени пользователя.

```
C:\Users\*\AppData\Roaming\Microsoft\SystemCertificates\My\Certificates
C:\Certs
```

Отсутствующий или битый конфиг — понятное сообщение в интерфейсе и запись в лог, без падения.

### 3.2. Сканирование директорий и парсинг [кейс]

Для каждой директории из конфига найти файлы сертификатов и извлечь из каждого:

- серийный номер;
- имя владельца (CN из Subject);
- удостоверяющий центр (CN из Issuer);
- встроена ли лицензия КриптоПро (наличие специального расширения в сертификате).

Поддерживаемые файлы:

- `.cer` / `.crt` (DER и Base64) — читаются напрямую через `X509Certificate2`;
- файлы хранилища «Личное» из профиля пользователя (без расширения, имя = отпечаток) — это сериализованный элемент хранилища, сертификат лежит внутри в свойстве с идентификатором 32. **[проверить]** на стенде: установить тестовый `.p12` и убедиться, что файл появляется в `AppData\Roaming\Microsoft\SystemCertificates\My\Certificates`.

Нечитаемый файл не останавливает сканирование: ошибка в лог, идём дальше.

### 3.3. Удалённое сканирование ПК [кейс]

Админ задаёт список ПК. Для каждого приложение собирает сертификаты из директорий конфига и версию КриптоПро.

**[решение]** В интерфейсе для подключения принимается только IPv4. Отдельное необязательное поле «Название» позволяет подписать компьютер для администратора; подпись не используется как сетевой адрес. В списке показываются и название, и IPv4. Повторяющиеся IPv4 запрещены.

**[решение]** Первой в общем списке всегда находится строка «Этот компьютер».
Она не удаляется и не переименовывается; можно менять галочку выбора и дополнительные пути.
При первом появлении строка не выбрана. Логин, пароль и адрес для неё не вводятся.
Файлы, версия КриптоПро и хранилище «Личное» компьютера читаются локально с правами
текущего пользователя Windows, без SMB и службы RemoteRegistry. Выбор и пути сохраняются
в `computers.xml` версии 4 отдельным элементом `localComputer`; ранние форматы списка не поддерживаются. Отдельной вкладки «Папка» нет.

**[решение]** Для каждого ПК сканируются общие директории из выбранного XML и дополнительные директории из его профиля. В редакторе ПК дополнительные пути вводятся по одному на строку и проверяются по тем же правилам, что и общие, включая маски папок. При пустом списке сканируются только общие директории. Повторы путей после нормализации удаляются без учёта регистра.

**[решение]** Основной способ доступа — административная шара `\\ПК\C$` (SMB): путь `C:\...` из конфига превращается в `\\ПК\C$\...`. Плюсы: только стандартный `System.IO`, не нужен агент и дополнительные службы.

**[решение]** Для удалённых ПК приложение дополнительно собирает открытые сертификаты
из хранилища «Личное» компьютера (`certlm.msc`) через службу «Удалённый реестр».
Используется сохранённая учётная запись целевого ПК с правом чтения соответствующей ветки.
Ошибки хранилища отображаются в интерфейсе и журнале. Доступные сертификаты из папок
и хранилища остаются в результатах.

Версия КриптоПро **[проверить]**:

- основной вариант — версия файла из `\\ПК\C$\Program Files\Crypto Pro\CSP\` (и `Program Files (x86)`) через `FileVersionInfo`;
- запасной — реестр удалённого ПК (ветка `Uninstall`, `DisplayVersion` у «КриптоПро CSP») через WMI или Remote Registry.

Требования к поведению:

- ПК сканируются независимо: недоступный ПК, отказ в доступе, отсутствие КриптоПро — статус в интерфейсе и запись в лог, остальные продолжают сканироваться;
- интерфейс не зависает во время сканирования (фоновый поток);
- подключение выполняется с логином и паролем, указанными для целевого ПК. Учётной записи нужен доступ к его административным папкам.

### 3.4. Запись в БД [кейс]

- Если таблицы нет — создать, затем записать. Если есть — просто записать.
- Сертификат идентифицируется по серийному номеру. Если запись есть — обновить её и время обновления, **вторую строку не добавлять**.
- При первой записи время обновления равно времени внесения.
- Все значения передаются в SQL параметрами.

**[решение]** Таблица `Certificates` (организаторы обещали «структуру таблицы», но в материалах её нет — см. вопросы):

| Столбец | Тип | Смысл |
|---|---|---|
| `SerialNumber` | `NVARCHAR(128)`, первичный ключ | Серийный номер |
| `CreatedAt` | `DATETIME2(3)` | Дата и время внесения, UTC |
| `UpdatedAt` | `DATETIME2(3)` | Дата и время обновления, UTC |
| `OwnerName` | `NVARCHAR(512)` | Имя владельца |
| `CertificationAuthority` | `NVARCHAR(512)` | Удостоверяющий центр |
| `CryptoProVersion` | `NVARCHAR(64)`, NULL | Версия КриптоПро |
| `IsCryptoProLicenseEmbedded` | `BIT` | Встроена ли лицензия в сертификат |
| `ExpiresAtUtc` | `DATETIME2(0)`, NULL | Дата и время окончания действия в UTC |

Первичный ключ по серийному номеру гарантирует отсутствие дублей на уровне БД, даже если ошибётся код.

**[решение]** `CertificateLocations` хранит места обнаружения. Одна строка соответствует
серийному номеру, компьютеру и пути. Интерфейс подставляет срок действия из `Certificates`.
При удалении сертификата связанные строки удаляются по внешнему ключу.

### 3.5. Панель управления [кейс]

**[решение]** WinForms, одно окно:

- поле ввода и список ПК для сканирования (добавить / удалить);
- кнопка «Сканировать»;
- таблица результатов: ПК, статус, версия КриптоПро, найденные сертификаты;
- строка состояния с ходом работы и ошибками.

### 3.6. Логирование [кейс]

**[решение]** Папка `logs` находится рядом с папкой `configs`. В `telecom.log` записываются запуск и выход, начало и конец сканирования каждого ПК, запись в БД и ошибки. В `telecomErrors.log` дублируются ошибки с текстом и стеком исключений, в том числе из глобальных обработчиков интерфейса и фоновых потоков. Запись потокобезопасна.

Задать как можно раньше — от ответов зависят задачи B и C.

1. Какой способ удалённого доступа доступен на проверочном стенде: админ-шары `C$`, WMI, Remote Registry, WinRM? Домен или рабочая группа?
2. Где структура таблицы БД, заявленная в исходных данных? Обязательны ли конкретные имена таблицы и столбцов?
3. «Если это лицензия Крипто Про, то указать версию» — это версия КриптоПро CSP, установленного на ПК, где найден сертификат?
4. Как определять «лицензия встроена в сертификат»: по расширению с OID лицензии КриптоПро (предположительно `1.2.643.2.2.49.2`)? Дадут ли тестовый сертификат с таким расширением? В выданных его нет.
5. «Личные сертификаты» — хранилища всех пользователей ПК или только текущего?
6. Нужно ли хранить, с какого ПК получен сертификат? В списке полей этого нет.

## 5. Задачи

Четыре направления идут параллельно после задачи A1. Внутри направления — по порядку.

### A. Каркас и стенд

- **A1. Решение и общие модели.** Создать `.sln` и WinForms-проект под .NET 4.5, `.gitignore`. Описать общие классы данных: «сертификат» (поля из 3.2), «результат сканирования ПК» (имя, статус, версия КриптоПро, список сертификатов). *Готово, когда:* пустое окно собирается в `.exe`, классы лежат в репозитории. **Блокирует всё остальное — сделать первым.**
- **A2. Логгер.** Класс записи в файл в формате из кейса, потокобезопасный; глобальные обработчики исключений. *Готово, когда:* брошенное в любом потоке исключение попадает в файл с миллисекундами.
- **A3. Стенд.** Две Windows 10 (ВМ) в одной сети, на «клиенте» — КриптоПро 5.0 и тестовые `.p12` в хранилище «Личное», на «админе» — MSSQL 2019. Проверить допущения из 3.2 и 3.3: где лежат файлы сертификатов, доступна ли `C$`, откуда читается версия КриптоПро. *Готово, когда:* результаты проверки записаны в этот документ вместо пометок [проверить].

### B. Сертификаты

- **B1. Чтение конфига.** Список директорий и строка подключения, обработка ошибок. *Готово, когда:* корректный конфиг читается, битый даёт понятную ошибку в лог.
- **B2. Парсер сертификатов.** `.cer` (DER и Base64) и файлы хранилища → модель сертификата. *Готово, когда:* оба тестовых сертификата (Иванов, Петров) разбираются в обоих видах; серийный номер, владелец и УЦ совпадают с тем, что показывает Windows.
- **B3. Признак встроенной лицензии.** Поиск расширения лицензии КриптоПро. Зависит от ответа на вопрос 4. *Готово, когда:* для тестовых сертификатов — «нет»; для сертификата с расширением (если дадут) — «да».
- **B4. Сканер директорий.** Обход директорий из конфига с раскрытием `*`, вызов парсера для каждого файла, пропуск нечитаемых с записью в лог. *Готово, когда:* локальная папка с тестовыми файлами и мусором даёт ровно два сертификата и записи в логе об остальном.

### C. Удалённый сбор

- **C1. Доступ к ПК.** Преобразование путей конфига в `\\ПК\C$\...`, проверка доступности ПК, различимые статусы: «недоступен», «нет доступа», «успешно». *Готово, когда:* на стенде сканер B4 находит сертификаты на втором ПК.
- **C2. Версия КриптоПро.** Определение версии на удалённом ПК, включая случай «не установлен». *Готово, когда:* на стенде возвращается `5.0.13003`, на ПК без КриптоПро — пустое значение без исключения.
- **C3. Сканирование списка ПК.** Объединить C1, C2 и B4: список ПК → список результатов; сбой одного ПК не мешает остальным. *Готово, когда:* из списка «рабочий ПК + несуществующий ПК» получаем один успех и одну ошибку.

### D. База данных

- **D1. Создание таблицы.** Проверка существования и создание по схеме из 3.4. *Готово, когда:* на пустой БД таблица создаётся, повторный запуск не падает.
- **D2. Запись без дублей.** Вставка или обновление по серийному номеру, параметризованный SQL, времена по правилам из 3.4. *Готово, когда:* два прогона подряд дают то же число строк, `CreatedAt` не изменился, `UpdatedAt` обновился.

### E. Интерфейс и сдача

- **E1. Панель управления.** Окно из 3.5, сканирование в фоне, вывод результатов и статусов. Начинать сразу после A1 на заглушках, подключить C3 и D2 по готовности.
- **E2. Сквозная проверка на стенде.** Полный сценарий: пустая БД → сканирование → повторное сканирование → недоступный ПК → битый конфиг → недоступная БД. Сверить лог с форматом кейса.
- **E3. Сдача.** Проход по коду на соответствие требованиям оформления, инструкция по запуску в README, сборка итогового `.exe`, сценарий демонстрации.

### Распределение на двоих (Mac + Windows)

Код делится на два проекта в одном решении:

- **`Core` — библиотека классов под .NET 4.5** без интерфейса и без обращений к сети: логгер, конфиг, парсер, сканер директорий, работа с БД, логика обхода списка ПК. Пишется и проверяется на Mac.
- **`App` — WinForms-приложение**, ссылается на `Core`: окно, доступ к удалённым ПК, версия КриптоПро. Пишется только на Windows.

Граница между ними — интерфейс «доступ к ПК» (дать список файлов в директории, прочитать файл, вернуть версию КриптоПро). `Core` работает через интерфейс и тестируется на подставной реализации с локальными папками; настоящую реализацию для `\\ПК\C$` пишет Windows-разработчик.

Windows-разработчик вливает изменения и запускает тесты `Core` у себя минимум раз в несколько часов, а не в конце.

### Порядок и зависимости

```
A1 ──► A2, B1, B2, D1, E1 (параллельно)
A3 ──► уточняет B2, C1, C2
B1 + B2 ──► B4 ──► C1 ──► C3
B2 ──► B3 (после ответа организаторов)
D1 ──► D2
C3 + D2 ──► E1 (подключение) ──► E2 ──► E3
```

Минимум для засчитываемого результата: A1, A2, B1, B2, B4, C1, C3, D1, D2, E1. Задачи B3 и C2 закрывают два оставшихся поля таблицы.

## 6. Риски

- **Нет доступа к `C$` на стенде организаторов.** В рабочей группе админ-шары по умолчанию закрыты для локальных учётных записей. Поэтому вопрос 1 — первый, а доступ к ПК (C1) изолирован в одном классе, чтобы заменить способ без переписывания остального.
- **Сборка только на Windows.** .NET Framework 4.5 не собирается и не запускается на macOS / Linux — каждому разработчику нужна Windows или ВМ с Visual Studio.
- **Нет тестового сертификата с лицензией КриптоПро.** Без него B3 нельзя проверить на положительном случае.
- **ГОСТ-сертификаты.** Реальные сертификаты будут с ГОСТ-алгоритмами, тестовые — RSA. Поля, которые нам нужны, читаются без поддержки алгоритма, но это стоит проверить на любом публичном ГОСТ-сертификате.
