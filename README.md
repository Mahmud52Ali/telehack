# Сбор сведений о сертификатах СКЗИ

Приложение администратора для Windows 10, C# / .NET Framework 4.5.
Условия организаторов находятся в [Conditions/TASK.md](Conditions/TASK.md),
техническое задание команды — в [ТЗ.md](ТЗ.md).

## Что работает

Первой в списке «Компьютеры» всегда находится строка «Этот компьютер».
Её нельзя удалить или переименовать. Галочка включает или исключает локальный ПК
из сканирования; при первом появлении она снята. Через «Изменить» задаются дополнительные пути.
Логин, пароль и IPv4 для этой строки не вводятся: файлы, версия КриптоПро и хранилище
«Личное» компьютера читаются локально с правами текущего пользователя Windows.
SMB и служба «Удалённый реестр» для этого не нужны. Выбор и пути сохраняются между запусками.

Для удалённых ПК администратор задаёт IPv4 и при желании
подписывает его в отдельном поле «Название», например «Бухгалтерия — Иванов».
Для подключения принимается только полный IPv4 вида `192.168.56.101`; сетевые имена,
IPv6 и адреса с портом не допускаются. Название служит только подписью.
Администратор указывает логин и пароль для каждого удалённого ПК и отмечает нужные строки галочками. После открытия
окна приложение автоматически подключает отмеченные сохранённые удалённые ПК в фоне.
Кнопка «Подключить выбранные» повторяет подключение без сканирования.
«Сканировать» сначала повторно подключает выбранные удалённые ПК, затем сканирует доступные и выбранный локальный ПК;
ошибка подключения одного ПК не мешает обработке остальных.

Для удалённых ПК приложение проверяет TCP-порт SMB 445, устанавливает SMB-сеанс с помощью
Windows API, преобразует пути дисков в
административные UNC-пути (`D:\Certs` → `\\192.168.56.101\D$\Certs`), раскрывает маски
пользовательских папок и собирает сертификаты существующим файловым сканером.
На сканируемый ПК наше приложение не устанавливается, команды на нём не запускаются.

В поле «Учётная запись» укажите логин вида `ИМЯ-ПК\пользователь` или
`ДОМЕН\пользователь`. Для сканирования нужны права на чтение настроенных папок целевого ПК.

При сканировании приложение также читает открытые сертификаты из раздела «Личное»
самого компьютера (`certlm.msc`). На удалённом ПК нужна работающая служба
«Удалённый реестр» (`RemoteRegistry`), а у сохранённой учётной записи должны быть
права на чтение `HKLM\SOFTWARE\Microsoft\SystemCertificates\My\Certificates`.
Если хранилище недоступно, причина отображается во вкладке «Ошибки», а собранные
из папок сертификаты остаются в результатах.

IPv4, названия, галочки, логины и дополнительные пути сохраняются в
`configs/computers.xml`. Пароли хранятся в диспетчере учётных данных текущего пользователя Windows, в записях
`Telecom/Computer/<идентификатор>`. Пароли не записываются в XML и журнал.
При изменении ПК пустое поле пароля сохраняет прежний пароль той же учётки;
для другой учётки пароль вводится заново. Удаление ПК удаляет его сохранённый секрет.
На другой компьютер можно скопировать папку `configs`. Пароли на нём потребуется ввести заново.

Список хранится в формате версии 4: настройки «Этого компьютера» находятся в отдельном
элементе `localComputer` без адреса и учётных данных. Файлы ранних версий 1–3 не читаются:
приложение показывает ошибку и не перезаписывает файл — удалите его и добавьте ПК заново.
Если у сохранённого удалённого ПК нет логина, откройте «Изменить» и укажите логин и пароль для подключения.
Одинаковые названия допустимы, одинаковые IPv4 в списке запрещены.

Статус «SMB подключено» подтверждает соединение с `IPC$`; права чтения настроенных
папок проверяются при сканировании. Ошибка Windows `1219` означает существующее
соединение с другой учёткой: приложение показывает причину и не разрывает чужие сеансы.
При закрытии программы соединения Windows также не разрываются.
Таймаут XML ограничивает только TCP-проверку. Ожидание авторизации и чтения
файлов или реестра определяется Windows. Отмена и закрытие окна дожидаются текущего системного вызова.

Версия КриптоПро читается из **ProductVersion** файла `csptest.exe`, а не FileVersion:
версия отдельного файла может отличаться от версии установленного продукта.
Проверяются пути из конфигурации, включая `Program Files (x86)`.
`5.0.13003.0` отображается как `5.0.13003`; ненулевая четвёртая часть сохраняется.
Если ни один файл не найден, отображается «не найден в настроенных путях».
Отказ доступа или некорректная версия показываются как ошибка определения версии,
а не как отсутствие продукта. Чтение версии из удалённого реестра пока не реализовано.

Результат различает завершённое сканирование, частичный сбор, отказ доступа,
недоступность ресурса, ошибку и отмену. В таблице ошибок есть категория, путь и причина.
Повторы одного файла при перекрытии путей не добавляются. Одинаковый сертификат
в разных местах показывается с каждым источником.

Программа рекурсивно читает настроенные папки и показывает
серийный номер, владельца, удостоверяющий центр и источник каждого сертификата.
Поддерживаются `.cer` и `.crt` в DER, Base64 и PEM, а также файлы без расширения
с сериализованным сертификатом Windows (свойство 32).

Колонка встроенной лицензии означает наличие расширения `1.2.643.2.2.49.2`.
Это не проверка действительности лицензии или подписи. У образцов организаторов
расширения нет; положительный случай с настоящей встроенной лицензией пока не проверен.
При отсутствии CN Windows может вернуть другое краткое имя владельца или УЦ.

Проверка выполняется в фоне. Повреждённые файлы и недоступные подпапки попадают
во вкладку «Ошибки». Доступные файлы продолжают обрабатываться. Полный журнал
`logs/telecom.log` содержит события и ошибки. Копии ошибок с текстом и стеком
исключений также записываются в `logs/telecomErrors.log`. Каждая строка журнала
содержит дату и время с точностью до миллисекунд. Оба файла дополняются между
запусками, журнал ошибок появляется при первой записанной ошибке.

Контейнеры `.p12` / `.pfx` и прочие неподдерживаемые расширения пропускаются.
Программа не устанавливает сертификаты и не импортирует закрытые ключи.
Файлы больше 4 МиБ пропускаются с ошибкой. Сканер также пропускает с ошибкой файл
или папку, если сам найденный объект является ссылкой. Ссылку внутри уже заданного
пути, например перенаправленную папку AppData\Roaming, может разрешить Windows.

После проверки каждого выбранного ПК, включая локальный, найденные сертификаты записываются в MSSQL
по строке подключения из рабочего XML. Приложение создаёт отсутствующую таблицу `dbo.Certificates`
и обновляет существующие строки по серийному номеру. При наличии прав оно создаёт и отсутствующую
базу. Даты внесения и обновления берутся с сервера MSSQL.

Столбец «База данных» показывает число добавленных и обновлённых записей или причину ошибки.
При ошибке записи находки остаются в окне, а обработка остальных ПК продолжается.

Во вкладке «База данных» есть две таблицы. «Реестр сертификатов» показывает одну строку на
серийный номер. «Сертификаты по компьютерам» показывает серийный номер, владельца,
удостоверяющий центр, IP компьютера, путь к файлу или запись хранилища и дату истечения.
Для локального сканирования вместо IP
показано имя компьютера. Повторная находка по тому же пути на том же ПК не добавляет строку.
Таблицы обновляются при открытии и по кнопке «Обновить».

Кнопка «Проверить наличие» в таблице «Сертификаты по компьютерам» проверяет все сохранённые
привязки. Для одной находки выберите «Проверить наличие» в меню строки по правой кнопке мыши.
Программа читает только сохранённый файл или конкретную запись «Личного» и сравнивает
серийный номер с ожидаемым. Один источник читается один раз для всех проверяемых строк.
Для удалённых ПК используются сохранённые профили, включая ПК со снятыми галочками сканирования.
Столбцы «Наличие» и «Проверено» показывают итог и местное время последней адресной проверки:
«Найден», «Не найден по этому пути», «Заменён другим сертификатом» или «Не удалось проверить».
Последний статус означает отсутствие профиля, недоступный ПК, отказ доступа или нечитаемые данные;
он не подтверждает отсутствие сертификата. До первой проверки отображается «Не проверялся».
При отмене уже полученные итоги сохраняются, непрочитанные пути сохраняют прежние статусы.
Проверка не меняет даты внесения и обновления самого сертификата и ничего не удаляет.

Обе таблицы показывают дату истечения в местном времени. Оранжевая ячейка означает, что осталось
до 30 дней, красная — что срок истёк; если срок неизвестен, стоит «—».
При первом сохранении результатов приложение создаёт отсутствующие таблицы `dbo.Certificates`
и `dbo.CertificateLocations`; для этого нужно право `CREATE TABLE` с записью в схему `dbo`.
Существующие таблицы приложение не изменяет: если они созданы ранней версией без столбцов
`ExpiresAtUtc`, `CheckStatus` и `CheckedAtUtc`, удалите их — при следующем сканировании они
создадутся заново.

В реестре «×» удаляет сертификат со всеми привязками. В таблице «Сертификаты по компьютерам»
«×» удаляет выбранную находку и показывает в подтверждении ПК, на которых остаются другие
копии. При удалении последней находки удаляется и запись в реестре. Подтвердите действие
полным серийным номером. Для удаления нужны права `DELETE` на соответствующие таблицы.
Программа запишет результат в журнал.
Если сертификат снова найдётся при сканировании, его запись появится в базе заново.

Шаблон конфигурации содержит путь к «Личному» пользовательских профилей под
`C:\Users`. Для профилей в других каталогах укажите соответствующие пути.

## Конфигурация

При запуске сборки из репозитория папки `configs` и `logs` создаются в корне
репозитория рядом с `Telecom.sln`. В отдельной поставке они создаются рядом с `Telecom.App.exe`.
Расположение определяется по каталогу `.exe` и его родительским папкам.
Если в эту папку нельзя писать (например, программа лежит в `Program Files`),
`configs` и `logs` создаются в `%LOCALAPPDATA%\Telecom`.

- `scan.config.xml` — общие пути сканирования, таймаут, пути к `csptest.exe` и настройки MSSQL.
- `computers.xml` — список ПК, галочки, логины и дополнительные пути для каждого ПК. При новой установке файл появляется при первом сохранении списка.

Откройте «Настройки» в правом верхнем углу приложения.

- **Сканирование.** Общие папки с сертификатами, пути к `csptest.exe` и таймаут для
  TCP-порта 445. Оба списка прокручиваются, а удаление пути требует подтверждения.
- **База данных.** Вставьте строку подключения MSSQL. Кнопка «Проверить подключение»
  проверяет вход в указанную базу. Нажмите «Сохранить», чтобы применить изменения.
- **Файлы и журнал.** «Просмотреть XML» показывает рабочий файл, а «Перейти» выделяет
  нужный файл в Проводнике. «Сохранить копию XML…» экспортирует сохранённый
  `scan.config.xml` вместе со строкой подключения. «Загрузить XML…» проверяет выбранный
  файл и после подтверждения заменяет им рабочий `scan.config.xml`. «Восстановить настройки
  первого запуска…» возвращает содержимое шаблона, включая пустую строку MSSQL.
- **Персонализация.** Выберите светлую, тёмную или системную тему и масштаб
  шрифта от 80 до 150%. Светлая тема и 100% используются по умолчанию.
  Системная тема следует за цветовым режимом приложений Windows. Изменения
  применяются сразу и сохраняются отдельно в `configs/appearance.xml`.

При запуске приложение создаёт отсутствующий `configs/scan.config.xml` из шаблона
`scan.config.template.xml`.

Пути из раздела `<directories>` общие для всех выбранных ПК и относятся к их дискам.

```xml
<scanSettings connectionTimeoutSeconds="3">
  <directories>
    <directory>C:\Users\*\AppData\Roaming\Microsoft\SystemCertificates\My\Certificates</directory>
    <directory>D:\Certs</directory>
  </directories>
  <cryptoProExecutables>
    <path>C:\Program Files\Crypto Pro\CSP\csptest.exe</path>
    <path>C:\Program Files (x86)\Crypto Pro\CSP\csptest.exe</path>
  </cryptoProExecutables>
  <connectionString>Server=YOUR_SQL_SERVER;Database=Certificates;Integrated Security=True;Connect Timeout=5</connectionString>
</scanSettings>
```

Для удалённого ПК откройте «Добавить» или «Изменить», для строки «Этот компьютер» — «Изменить», и заполните поле
«Дополнительные пути». Введите по одному пути на строку, например `D:\Certificates`.
Для этого ПК приложение проверит все общие пути из рабочего XML и его дополнительные пути.
Пустое поле оставляет только общие пути. Приложение пропускает пустые строки
и показывает причину отклонения неверного пути перед сохранением. Повторы
нормализованных путей удаляются без учёта регистра.

`*` заменяет полное имя папки; допускается несколько таких сегментов. Частичные маски
вроде `Ivan*`, относительные пути, переходы `..`, IPv6 и порты в имени ПК не поддерживаются.
Пустые и некорректные настройки показываются как ошибка и записываются в журнал.
DTD и внешние XML-сущности запрещены. Для записи в MSSQL заполните строку подключения
во вкладке «База данных», подставив имя сервера и базы по примеру выше. Шаблон содержит пустую
строку подключения. Пустой или отсутствующий `connectionString` включает сканирование без записи в БД.
Реальные пароли и локальные настройки не добавляйте в отслеживаемый пример.

Если у отдельного профиля нет заданной папки, он пропускается с записью в журнал.
Для маски пользовательского хранилища «Личное» доступный каталог профилей без папок
сертификатов считается пустым результатом. Отсутствующий корень маски, произвольная
маска без совпадений и отказ доступа отображаются в ошибках.
Служебные ссылки в корневой папке профилей `Users`, ведущие в `ProgramData`
или `Users\Default` того же диска и ПК, пропускаются при раскрытии маски с записью
в журнале. Назначение читается из метаданных ссылки, поэтому её имя и язык Windows
не влияют на результат. Пропуск остальных ссылок и ошибки чтения их назначения
отображаются в ошибках сканирования.

## Структура проекта

Решение из трёх проектов. Папка внутри проекта совпадает с пространством имён
(`src/Telecom.Core/Scanning` → `Telecom.Core.Scanning`), в одном файле — один класс (перечисления его статусов лежат рядом с ним).

```
src/Telecom.Core/            логика без Windows API и интерфейса
  Access/                    интерфейсы доступа к ПК: файлы, хранилище «Личное», SMB-подключение
  Certificates/              CertificateParser (DER, Base64/PEM, файл хранилища) и CertificateInfo
  Common/                    RemotePath (C:\... → \\IP\C$\...), AtomicFile, SafeXml
  Computers/                 ComputerProfile и файл списка ПК computers.xml
  Configuration/             ScanConfiguration и чтение/запись scan.config.xml
  Database/                  DatabaseConnection, DatabaseSchema, CertificateWriter/Reader/Deleter
  Locations/                 «Проверить наличие»: LocationCheckCoordinator и CertificateLocationChecker
  Logging/                   FileLogger: время до миллисекунд, копия ошибок в отдельный файл
  Scanning/                  ScanCoordinator, ComputerScanner, DirectoryScanner, версия КриптоПро
src/Telecom.App/             WinForms-приложение (.exe)
  Program.cs, AppPaths.cs    запуск, один экземпляр, расположение configs и logs
  ErrorReporter.cs           показ ошибок и перехват необработанных исключений
  OperationGate.cs           одна длительная операция за раз, отмена, закрытие после завершения
  Windows/                   реализации интерфейсов Access через SMB, реестр и диспетчер учётных данных
  Forms/                     MainForm и страницы: Scan, Database, Settings, общие элементы Common
  Theming/                   светлая и тёмная тема, масштаб шрифта
tests/Telecom.Tests/         исполняемые проверки; папки повторяют Core, Support — помощники, Fakes — заглушки
```

Основной сценарий: `ScanPage` → `ScanCoordinator` (подключить выбранные ПК → `ComputerScanner`
→ `CertificateWriter`). Координатор сообщает ход работы событиями, окно только показывает их.
`Core` не ссылается на `App`, поэтому сценарии проверяются без сети, SMB и MSSQL.

## Сборка и запуск

Нужны Windows, .NET SDK с MSBuild и установленный .NET Framework 4.5 или новее
для запуска. Пакет reference assemblies **именно 4.5** восстанавливается из NuGet;
устанавливать старый runtime поверх системного .NET Framework не нужно.

В PowerShell из корня репозитория:

```powershell
dotnet build Telecom.sln -c Release
& .\src\Telecom.App\bin\Release\net45\Telecom.App.exe
```

Для локальной проверки выделите строку «Этот компьютер», нажмите «Изменить»
и добавьте полный путь к папке `Test_sert` в дополнительные пути.
Отметьте строку галочкой и нажмите «Сканировать».
В результатах должны быть сертификаты Иванова и Петрова с источниками из `Test_sert`.
Контейнеры `.p12` и `README.md` будут пропущены. Также проверяются общие пути из XML
и хранилище «Личное» компьютера, поэтому возможны дополнительные находки и ошибки доступа.
Примеры организаторов не изменяются.

Для проверки удалённого ПК нажмите «Добавить»,
введите IPv4, логин, пароль и при желании название. После сохранения начнётся подключение.
Отметьте нужные ПК, проверьте пути в выбранной конфигурации и нажмите «Сканировать».
После перезапуска те же отмеченные ПК подключатся автоматически; сканирование
запускается отдельной кнопкой.
Приложение не открывает общий доступ и не меняет настройки целевого компьютера.
Доступ к SMB и административной папке должен быть подготовлен
администратором. Открытый порт 445 не подтверждает наличие доступа к `C$`/`D$`:
права проверяет Windows при чтении самих папок. Для проверки хранилища компьютера
на стенде добавьте публичный тестовый сертификат в «Личное» через `certlm.msc` на
целевом ПК. При сканировании с ПК администратора сверьте серийный номер и источник «Реестр».
Автоматические проверки используют подставной доступ к SMB и удалённому реестру.
`connectionTimeoutSeconds` (1–60) ограничивает только установление TCP-соединения;
последующее чтение файлов и реестра зависит от системных таймаутов Windows.
Кнопка отмены останавливает дальнейший обход, но не прерывает уже начатый блокирующий
системный вызов.

Для запуска нужны права записи в корень репозитория или в отдельную папку поставки.
Для переноса программы сохраняйте рядом `.exe`, `Telecom.Core.dll`,
`Telecom.App.exe.config` и `scan.config.template.xml` из папки сборки. Установка SDK на целевой ПК администратора
не нужна; на сканируемые ПК наше приложение не копируется.

## Проверки

```powershell
dotnet build Telecom.sln -c Release
& .\tests\Telecom.Tests\bin\Release\net45\Telecom.Tests.exe
```

Это небольшой исполняемый набор проверок без дополнительного тестового фреймворка.
Код возврата `0` означает успех. Проверки окна и Windows API (WinForms, реестр, SMB,
диспетчер учётных данных) вне Windows выводятся как `SKIP`; на macOS их можно запустить через
`mono`, но полный прогон выполняется только на Windows. Образцы находятся автоматически по папке `Test_sert`
в родительских каталогах; при необходимости путь можно передать первым аргументом.

Проверяются исходные сертификаты организаторов, текстовые и сериализованные форматы,
повреждённые данные, отказ от чтения ключевых контейнеров, продолжение обхода после
ошибки, отмена, ограничение размера и параллельное логирование. Отказ доступа и ссылка
моделируются адаптером без изменения ACL, служб Windows или хранилища сертификатов.
Дополнительно проверяются выбор каталога для конфигурации и журнала,
создание и сохранение рабочего XML в `configs`,
ошибки XML, построение UNC-путей, маски профилей,
диски C:/D:, частичный сбор, сетевые ошибки, закрытая административная папка,
поиск КриптоПро по двум путям и нормализация ProductVersion.
Проверки списка ПК охватывают раздельное сохранение IPv4 и названий, строгую проверку IPv4,
сохранение галочек, дубли, повреждённый XML,
автоподключение после открытия окна, пропуск невыбранного ПК и продолжение после
недоступного ПК. Проверяются обязательность учётных данных для подключения и чтение
сертификатов после авторизации с сохранённой учёткой ПК.
Проверки дополнительных путей охватывают хранение, проверку ввода,
объединение путей отдельно для каждого ПК, перекрытие папок и продолжение после отказа доступа.
Проверка окна охватывает объединение файловых и реестровых находок, отказ доступа
к хранилищу компьютера, повреждённые записи и продолжение сканирования.
Проверки диспетчера учётных данных создают только собственные записи со случайными
идентификаторами и вымышленными паролями, обновляют их и удаляют в `finally`.
Настоящие учётки и сетевые соединения пользователя эти проверки не читают и не изменяют.
Все временные данные создаются в системной временной папке и удаляются после проверок.

Проверки MSSQL (схема, запись, чтение, подсветка срока и удаление из обеих таблиц) выполняются,
если задана переменная окружения `TELECOM_TEST_SQL` со строкой подключения к отдельной базе,
имя которой оканчивается на `Tests`. Они пересоздают в ней `dbo.Certificates` и `dbo.CertificateLocations`.
Они также создают и удаляют на том же сервере базу `TelecomCreateTests` и временную учётную запись
`telecom_restricted_test`, поэтому учётной записи проверок нужны права администратора сервера.
Без переменной эти проверки пропускаются с пометкой `SKIP`.
