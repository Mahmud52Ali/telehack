# Telecom — сбор сведений о СКЗИ

Приложение для сбора сертификатов и версии КриптоПро CSP с компьютеров локальной сети. Результаты отображаются в интерфейсе и сохраняются в Microsoft SQL Server.

**Стек:** C# 5 · .NET Framework 4.5 · Windows Forms · Microsoft SQL Server · XML · SMB · RemoteRegistry.

Программа запускается на **ПК администратора**. На **сканируемых ПК** используются штатные службы Windows; устанавливать Telecom на них не требуется.

## Сборка и запуск

На ПК администратора потребуются:

- Windows 10 с .NET Framework 4.5 или новее.
- .NET SDK и доступ к NuGet для сборки.
- Доступный Microsoft SQL Server для сохранения результатов.

В PowerShell из корня репозитория:

```powershell
dotnet build Telecom.sln -c Release
& .\src\Telecom.App\bin\Release\net45\Telecom.App.exe
```

Зависимости восстанавливаются автоматически. Устанавливать старый .NET Framework 4.5 поверх более новой системной версии не нужно.

Для переноса приложения скопируйте содержимое `src\Telecom.App\bin\Release\net45` целиком. Для запуска готовой сборки SDK не требуется.

Приложению нужна доступная для записи папка конфигурации и журналов. Если папка приложения недоступна для записи, используется `%LOCALAPPDATA%\Telecom`.

## Подготовка сканируемых компьютеров

Выполните следующие семь шагов на каждом сканируемом ПК. Команды выполняются на нём, кроме отдельно отмеченного действия в шаге 7.

### 1. Подключите компьютер к локальной сети

Сканируемый ПК должен быть доступен с ПК администратора по IPv4.

Для виртуальной машины выберите в настройках сетевого адаптера **«Сетевой мост / Bridged»** и адаптер, подключённый к локальной сети. В Hyper-V используйте **внешний виртуальный коммутатор**.

Если используется VPN, проверьте, что он разрешает доступ к локальной сети и не направляет подключения к сканируемым ПК через VPN-туннель.

### 2. Откройте PowerShell и определите адрес компьютера

На сканируемом ПК откройте **«Пуск → Windows PowerShell → Запуск от имени администратора»**. На 64-разрядной Windows выбирайте версию без пометки `x86`.

Узнайте имя компьютера:

```powershell
hostname
```

Посмотрите сетевые адреса:

```powershell
ipconfig
```

Запишите **имя компьютера** и **IPv4 подключённого сетевого адаптера**. Они понадобятся при добавлении ПК в приложение.

### 3. Настройте сетевой профиль

Посмотрите сетевые подключения:

```powershell
Get-NetConnectionProfile
```

Найдите подключение к локальной сети и его `InterfaceIndex`.

Если `NetworkCategory` уже имеет значение `Private` или `DomainAuthenticated`, переходите к следующему шагу.

Для профиля `Public` выполните:

```powershell
$scanInterfaceIndex = [int](Read-Host "Введите InterfaceIndex подключения к локальной сети")
Set-NetConnectionProfile -InterfaceIndex $scanInterfaceIndex -NetworkCategory Private
```

Проверьте результат:

```powershell
Get-NetConnectionProfile
```

У нужного подключения ожидается `NetworkCategory : Private`.

### 4. Создайте учётную запись для сканирования

Запросите пароль для нового пользователя:

```powershell
$scanPassword = Read-Host "Введите пароль для scanadmin" -AsSecureString
```

Введите непустой пароль и сохраните его для последующего ввода в приложении. Символы при вводе скрываются.

Создайте пользователя:

```powershell
New-LocalUser -Name "scanadmin" -Password $scanPassword -Description "Telecom scanning"
```

Добавьте его в группу локальных администраторов:

```powershell
Add-LocalGroupMember -SID "S-1-5-32-544" -Member "$env:COMPUTERNAME\scanadmin"
```

`S-1-5-32-544` — идентификатор группы администраторов, одинаковый для русской и английской Windows. Эти права нужны для доступа через административные общие ресурсы дисков.

Проверьте членство в группе:

```powershell
Get-LocalGroupMember -SID "S-1-5-32-544"
```

Выведите и запишите полный логин для приложения:

```powershell
"$env:COMPUTERNAME\scanadmin"
```

Получится строка вида `PC-01\scanadmin`.

Если используется существующая доменная учётная запись с правами локального администратора на сканируемом ПК, создание отдельного пользователя не требуется.

### 5. Разрешите удалённые административные подключения

Для созданной локальной учётной записи выполните:

```powershell
New-ItemProperty `
    -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" `
    -Name "LocalAccountTokenFilterPolicy" `
    -PropertyType DWord -Value 1 -Force
```

Настройка снимает фильтрацию административных прав UAC при сетевом входе. Без неё обращение к `C$` может завершаться ошибкой «Отказано в доступе» даже с правильными учётными данными.

**Изменение распространяется на всех локальных администраторов этого ПК.** Значение `0` возвращает фильтрацию. Для доменной учётной записи этот шаг не требуется. [Описание настройки Microsoft](https://learn.microsoft.com/en-us/troubleshoot/windows-client/networking/cannot-logon-access-administrative-share).

### 6. Включите службы и проверьте общие ресурсы

Включите автоматический запуск службы **«Сервер»** и запустите её. Она обеспечивает доступ к файлам через SMB:

```powershell
Set-Service -Name LanmanServer -StartupType Automatic
Start-Service -Name LanmanServer
```

Включите и запустите службу **«Удалённый реестр»**. Она нужна для чтения хранилища «Личное» компьютера:

```powershell
Set-Service -Name RemoteRegistry -StartupType Automatic
Start-Service -Name RemoteRegistry
```

Проверьте состояние:

```powershell
Get-Service -Name LanmanServer, RemoteRegistry
```

Сразу после запуска у обеих служб ожидается статус `Running`.

Посмотрите общие ресурсы:

```powershell
Get-SmbShare
```

В списке должны присутствовать:

- `C$` с путём `C:\`;
- `IPC$`;
- ресурсы остальных сканируемых дисков, например `D$` для диска `D:`.

**Если `C$` отсутствует**, включите автоматическое создание административных ресурсов:

```powershell
New-ItemProperty `
    -Path "HKLM:\SYSTEM\CurrentControlSet\Services\LanmanServer\Parameters" `
    -Name "AutoShareWks" -PropertyType DWord -Value 1 -Force
```

Перезагрузите сканируемый ПК и повторите `Get-SmbShare`.

Учётной записи сканирования нужны права чтения настроенных папок и ветки реестра:

```text
HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\SystemCertificates\My\Certificates
```

### 7. Разрешите подключение в брандмауэре

Сначала **на ПК администратора** выполните:

```powershell
ipconfig
```

Запишите его IPv4 в локальной сети, общей со сканируемым ПК.

Затем **на сканируемом ПК**, в PowerShell администратора, выполните следующий блок. При запросе введите найденный адрес ПК администратора:

```powershell
$scanAdminIp = Read-Host "Введите IPv4 ПК администратора"

if (Get-NetFirewallRule -Name "Telecom-SMB" -ErrorAction SilentlyContinue) {
	Set-NetFirewallRule -Name "Telecom-SMB" `
		-Direction Inbound -Action Allow -Enabled True `
		-Protocol TCP -LocalPort 445 `
		-RemoteAddress $scanAdminIp -Profile Private,Domain
} else {
	New-NetFirewallRule -Name "Telecom-SMB" -DisplayName "Telecom SMB" `
		-Direction Inbound -Action Allow -Enabled True `
		-Protocol TCP -LocalPort 445 `
		-RemoteAddress $scanAdminIp -Profile Private,Domain
}
```

Команды разрешают входящие подключения к TCP-порту `445` с ПК администратора. При повторном выполнении существующее правило обновляется.

**Здесь вводится адрес ПК администратора. В список компьютеров Telecom добавляется адрес сканируемого ПК.**

## Проверка подключения

На ПК администратора выполните:

```powershell
$scanComputerIp = Read-Host "Введите IPv4 сканируемого ПК"
Test-NetConnection -ComputerName $scanComputerIp -Port 445 -InformationLevel Detailed
```

Ожидается:

```text
TcpTestSucceeded : True
```

Проверьте также:

- `SourceAddress` — адрес ПК администратора, разрешённый в правиле брандмауэра;
- `InterfaceAlias` — подключение, через которое доступен сканируемый ПК.

Если выбирается VPN-интерфейс, настройте исключение для локальной сети в VPN и повторите проверку.

Успешная проверка порта подтверждает сетевую доступность SMB. Учётные данные и права чтения проверяются приложением при подключении и сканировании.

## Настройка приложения

### Папки и КриптоПро

Откройте **«Настройки → Сканирование»**.

Общие папки проверяются на всех выбранных компьютерах. По умолчанию задан путь к файловому хранилищу «Личное» пользовательских профилей:

```text
C:\Users\*\AppData\Roaming\Microsoft\SystemCertificates\My\Certificates
```

Указывайте абсолютные пути на дисках **сканируемого ПК**, например `C:\Certs`. Программа сама преобразует их в сетевые пути. Маска `*` заменяет имя папки целиком.

Для определения версии КриптоПро по умолчанию проверяются:

```text
C:\Program Files\Crypto Pro\CSP\csptest.exe
C:\Program Files (x86)\Crypto Pro\CSP\csptest.exe
```

При другом расположении КриптоПро измените эти пути. Версия читается из `ProductVersion` файла `csptest.exe`.

Таймаут подключения задаётся в пределах 1–60 секунд и относится только к TCP-порту `445`. Дальнейшее ожидание файлов и реестра определяется Windows.

Нажмите **«Сохранить»**.

### База данных

Для быстрой проверки подготовьте отдельную пустую базу `Certificates` в MSSQL. Учётной записи подключения нужны права чтения и изменения данных, создания таблиц. Для отдельной тестовой базы можно назначить роль `db_owner`.

В **«Настройки → База данных»** укажите строку подключения:

```text
Server=YOUR_SQL_SERVER;Database=Certificates;Integrated Security=True;Connect Timeout=5
```

Замените `YOUR_SQL_SERVER` именем своего сервера или экземпляра MSSQL. При `Integrated Security=True` используется учётная запись Windows, под которой запущено приложение.

Нажмите **«Проверить подключение»**, затем **«Сохранить»**.

Таблицы `dbo.Certificates` и `dbo.CertificateLocations` создаются автоматически при первой записи найденных сертификатов. Если база отсутствует, приложение также может создать её при наличии соответствующих прав. Кнопка проверки подключения проверяет вход в уже существующую базу.

Таблицы ранних версий автоматически не обновляются. Для проверки новой версии используйте отдельную пустую базу. Даты внесения и обновления хранятся в UTC и отображаются по местному времени ПК администратора.

Пустая строка подключения позволяет сканировать без сохранения в БД.

### Список компьютеров

В разделе **«Компьютеры»** нажмите **«Добавить»** и заполните:

| Поле | Значение |
|---|---|
| IPv4 | Адрес сканируемого ПК, полученный через `ipconfig` |
| Название | Необязательная подпись компьютера |
| Учётная запись | Логин из шага 4, например `PC-01\scanadmin` |
| Пароль | Пароль этой учётной записи |
| Дополнительные пути | Папки только для этого ПК, по одному пути на строку |

Дополнительные пути проверяются вместе с общими. Для подключения принимается только IPv4; повторяющиеся адреса запрещены.

После сохранения начинается подключение. При последующих запусках отмеченные удалённые ПК подключаются автоматически.

Строка **«Этот компьютер»** позволяет выполнить локальное сканирование с правами текущего пользователя Windows. Для неё не нужны учётные данные, SMB и RemoteRegistry. При первом запуске её галочка снята; дополнительные пути задаются через **«Изменить»**.

## Сканирование и просмотр результатов

1. Отметьте нужные компьютеры галочками.
2. Нажмите **«Сканировать»**. Перед сканированием программа повторит подключение к выбранным удалённым ПК.
3. Во вкладке **«Сертификаты»** просмотрите владельца, удостоверяющий центр, серийный номер, признак встроенной лицензии и источник.
4. В строке компьютера проверьте версию КриптоПро, статус сканирования и результат в столбце **«База данных»**.
5. Откройте **«База данных»** для просмотра сохранённых результатов.

В разделе базы данных доступны:

- **«Реестр сертификатов»** — одна запись на серийный номер.
- **«Сертификаты по компьютерам»** — компьютеры и источники, где обнаружены сертификаты.
- **«Обновить»** — повторное чтение данных из MSSQL.
- **«Проверить наличие»** — проверка сохранённых источников сертификатов.

Сроки действия подсвечиваются: оранжевым — осталось до 30 дней, красным — срок истёк. Кнопка **«×»** удаляет запись из БД после подтверждения серийным номером; сертификат на самом ПК сохраняется.

Ошибка одного компьютера не останавливает обработку остальных. Ошибки подключения и чтения отображаются во вкладке **«Ошибки»**, ошибки сохранения — в столбце **«База данных»**.

Кнопка **«Подключить выбранные»** повторяет подключение без сканирования. **«Отменить»** останавливает дальнейшую обработку после завершения текущего системного вызова Windows.

## Конфигурация и журналы

При первом запуске рабочий XML создаётся из поставляемого шаблона.

| Файл | Назначение |
|---|---|
| `configs\scan.config.xml` | Общие пути, таймаут, пути КриптоПро и строка подключения MSSQL |
| `configs\computers.xml` | Список ПК, галочки выбора, логины и дополнительные пути |
| `logs\telecom.log` | Полный журнал |
| `logs\telecomErrors.log` | Ошибки и исключения; появляется при первой записанной ошибке |

При запуске из репозитория папки `configs` и `logs` находятся рядом с `Telecom.sln`, в отдельной поставке — рядом с `.exe`. Если эта папка недоступна для записи, используется `%LOCALAPPDATA%\Telecom`.

Пароли удалённых ПК сохраняются в диспетчере учётных данных текущего пользователя Windows. При переносе конфигурации на другой ПК пароли потребуется ввести заново.

Рабочий XML можно просмотреть, загрузить или сохранить его копию через **«Настройки → Файлы и журнал»**.

## Типовые проблемы

| Ситуация | Что проверить |
|---|---|
| Таймаут подключения к порту `445` | IPv4 сканируемого ПК, сетевой адаптер ВМ, службу «Сервер», брандмауэр и маршрутизацию VPN |
| Порт доступен, вход не выполняется | Логин `ИМЯ-ПК\пользователь`, пароль и членство в локальных администраторах |
| «SMB подключено», но папки не читаются | Наличие `C$`/`D$`, права на папки и настройку `LocalAccountTokenFilterPolicy` |
| Не читается «Личное» компьютера | Службу RemoteRegistry и права чтения ветки сертификатов |
| Ошибка Windows `1219` | Уже существует соединение с этим ПК под другой учётной записью. Используйте ту же учётную запись или вручную завершите прежнее соединение |
| КриптоПро не найден | Наличие `csptest.exe` по настроенным путям |
| Сертификаты найдены, но не сохранены | Строку подключения, доступность MSSQL и права учётной записи |
| Изменился IP ПК администратора | Повторите шаг 7 подготовки сканируемого ПК с актуальным адресом |
