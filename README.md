# Сбор сведений о сертификатах СКЗИ

Приложение администратора для Windows 10, C# / .NET Framework 4.5.
Условия организаторов находятся в [Conditions/TASK.md](Conditions/TASK.md),
техническое задание команды — в [ТЗ.md](ТЗ.md).

## Что работает

В режиме «Компьютеры» администратор задаёт IPv4 каждого ПК и при желании
подписывает его в отдельном поле «Название», например «Бухгалтерия — Иванов».
Для подключения принимается только полный IPv4 вида `192.168.56.101`; сетевые имена,
IPv6 и адреса с портом не допускаются. Название служит только подписью.
Администратор указывает логин и пароль для каждого ПК и отмечает нужные строки галочками. После открытия
окна приложение автоматически подключает отмеченные сохранённые ПК в фоне.
Кнопка «Подключить выбранные» повторяет подключение без сканирования.
«Сканировать» сначала повторно подключает все выбранные ПК, затем обходит доступные;
ошибка подключения одного ПК не мешает обработке остальных.

Приложение проверяет TCP-порт SMB 445, устанавливает SMB-сеанс с помощью
Windows API, преобразует пути дисков в
административные UNC-пути (`D:\Certs` → `\\192.168.56.101\D$\Certs`), раскрывает маски
пользовательских папок и собирает сертификаты существующим файловым сканером.
На сканируемый ПК наше приложение не устанавливается, команды на нём не запускаются.

В поле «Учётная запись» укажите логин вида `ИМЯ-ПК\пользователь` или
`ДОМЕН\пользователь`. Для сканирования нужны права на чтение настроенных папок целевого ПК.

IPv4, названия, галочки, логины и дополнительные пути сохраняются в
`%LOCALAPPDATA%\Telecom\computers.xml`. Пароли хранятся в диспетчере учётных данных текущего пользователя Windows, в записях
`Telecom/Computer/<идентификатор>`. Пароли не записываются в XML и журнал.
При изменении ПК пустое поле пароля сохраняет прежний пароль той же учётки;
для другой учётки пароль вводится заново. Удаление ПК удаляет его сохранённый секрет.
Эти локальные настройки не входят в поставку и Git; на другом компьютере их нужно задать заново.

Списки версий 1 и 2 загружаются с пустыми дополнительными путями и прежними
идентификаторами учётных данных. В версии 1 прежний IPv4 остаётся адресом, а прежнее сетевое имя переносится в название,
а IPv4 нужно заполнить через «Изменить». До этого подключение такой записи не выполняется.
При следующем сохранении список записывается в формате версии 3.
Если у сохранённого ПК нет логина, откройте «Изменить» и укажите логин и пароль для подключения.
Одинаковые названия допустимы, одинаковые IPv4 в списке запрещены.

Статус «SMB подключено» подтверждает соединение с `IPC$`; права чтения настроенных
папок проверяются при сканировании. Ошибка Windows `1219` означает существующее
соединение с другой учёткой: приложение показывает причину и не разрывает чужие сеансы.
При закрытии программы соединения Windows также не разрываются.
Таймаут XML ограничивает только TCP-проверку; ожидание авторизации и файловых
операций определяется Windows. Отмена и закрытие окна дожидаются текущего системного вызова.

Версия КриптоПро читается из **ProductVersion** файла `csptest.exe`, а не FileVersion:
версия отдельного файла может отличаться от версии установленного продукта.
Проверяются пути из конфигурации, включая `Program Files (x86)`.
`5.0.13003.0` отображается как `5.0.13003`; ненулевая четвёртая часть сохраняется.
Если ни один файл не найден, отображается «не найден в настроенных путях».
Отказ доступа или некорректная версия показываются как ошибка определения версии,
а не как отсутствие продукта. Чтение версии из удалённого реестра пока не реализовано.

Результат различает полную проверку **настроенных папок**, частичную проверку,
отказ доступа, недоступность SMB, ошибку и отмену. В таблице ошибок есть категория,
путь и исходное сообщение. Повторы одного файла при перекрытии путей не добавляются;
одинаковый сертификат в разных местах остаётся отдельным обнаружением.

Прежний режим «Папка» сохранён для ручной проверки локального или UNC-каталога.

Программа рекурсивно читает выбранную локальную или UNC-папку и показывает
серийный номер, владельца, удостоверяющий центр и источник каждого сертификата.
Поддерживаются `.cer` и `.crt` в DER, Base64 и PEM, а также файлы без расширения
с сериализованным сертификатом Windows (свойство 32).

Колонка встроенной лицензии означает наличие расширения `1.2.643.2.2.49.2`.
Это не проверка действительности лицензии или подписи. У образцов организаторов
расширения нет; положительный случай с настоящей встроенной лицензией пока не проверен.
При отсутствии CN Windows может вернуть другое краткое имя владельца или УЦ.

Проверка выполняется в фоне. Повреждённые файлы и недоступные подпапки попадают
во вкладку «Ошибки»; доступные файлы продолжают обрабатываться. Файл `telecom.log`
рядом с `.exe` содержит события и исключения с временем до миллисекунд.
Распаковывайте приложение в папку, доступную для записи текущему пользователю.

Контейнеры `.p12` / `.pfx` и прочие неподдерживаемые расширения пропускаются.
Программа не устанавливает сертификаты и не импортирует закрытые ключи.
Файлы больше 4 МиБ и ссылки/junction пропускаются; пропущенные ссылки учитываются
как ошибки, чтобы результат не выглядел полной проверкой папки.

В режиме «Компьютеры» после проверки каждого ПК найденные сертификаты записываются в MSSQL
по строке подключения из выбранного XML. Приложение создаёт отсутствующую таблицу `dbo.Certificates`
и обновляет существующие строки по серийному номеру. При наличии прав оно создаёт и отсутствующую
базу. Даты внесения и обновления берутся с сервера MSSQL.

Столбец «База данных» показывает число добавленных и обновлённых записей или причину ошибки.
При ошибке записи находки остаются в окне, а обработка остальных ПК продолжается.
Режим «Папка» выводит результаты в окно.

Файловый сбор охватывает настроенные папки. Реестровые хранилища, нестандартные профили
и перенаправления требуют отдельной проверки.

## Конфигурация

Рабочие настройки находятся в `%LOCALAPPDATA%\Telecom`. Вставьте этот путь в адресную
строку Проводника, чтобы открыть папку.

- `scan.config.xml` — общие пути сканирования, таймаут, пути к `csptest.exe` и настройки MSSQL.
- `computers.xml` — список ПК, галочки, логины и дополнительные пути для каждого ПК.

При первом запуске приложение копирует в эту папку `scan.config.xml` из старой сборки,
если файл лежит рядом с `.exe`. Для новой установки оно использует `scan.config.template.xml`.
Существующая пользовательская копия сохраняется при обновлениях. Поле «Конфигурация»
показывает её путь. Через «Обзор…» можно выбрать другой XML на время текущего запуска.

Пути из раздела `<directories>` общие для всех выбранных ПК и относятся к их дискам.

```xml
<scanSettings connectionTimeoutSeconds="3">
  <directories>
    <directory>C:\Users\*\AppData\Roaming\Microsoft\SystemCertificates\My\Certificates</directory>
    <directory>D:\Certs</directory>
  </directories>
  <cryptoProExecutables>
    <path>C:\Program Files\Crypto Pro\CSP\csptest.exe</path>
    <path>C:\Program Files (x86)\Crypto Pro\CSP\csptest.exe</path>
  </cryptoProExecutables>
  <connectionString>Server=YOUR_SQL_SERVER;Database=Certificates;Integrated Security=True;Connect Timeout=5</connectionString>
</scanSettings>
```

В режиме «Компьютеры» откройте «Добавить» или «Изменить» и заполните поле
«Дополнительные пути». Введите по одному пути на строку, например `D:\Certificates`.
Для этого ПК приложение проверит все общие пути из выбранного XML и его дополнительные пути.
Пустое поле оставляет только общие пути. Приложение пропускает пустые строки
и показывает причину отклонения неверного пути перед сохранением. Повторы
нормализованных путей удаляются без учёта регистра.

`*` заменяет полное имя папки; допускается несколько таких сегментов. Частичные маски
вроде `Ivan*`, относительные пути, переходы `..`, IPv6 и порты в имени ПК не поддерживаются.
Пустые и некорректные настройки показываются как ошибка и записываются в журнал.
DTD и внешние XML-сущности запрещены. Для записи в MSSQL заполните `connectionString`
по примеру выше, подставив имя сервера и базы. Шаблон новой установки содержит пустую
строку подключения. Пустой или отсутствующий `connectionString` включает сканирование без записи в БД.
Реальные пароли и локальные настройки не добавляйте в отслеживаемый пример.

Если у отдельного профиля нет заданной папки, он пропускается с записью в журнал.
Если совпадений вообще нет, результат содержит ошибку «не найдено».
Отказ доступа к отдельному профилю не скрывается и делает результат частичным.

## Сборка и запуск

Нужны Windows, .NET SDK с MSBuild и установленный .NET Framework 4.5 или новее
для запуска. Пакет reference assemblies **именно 4.5** восстанавливается из NuGet;
устанавливать старый runtime поверх системного .NET Framework не нужно.

В PowerShell из корня репозитория:

```powershell
dotnet build Telecom.sln -c Release
& .\src\Telecom.App\bin\Release\net45\Telecom.App.exe
```

Для локальной проверки выберите вкладку «Папка», папку `Test_sert` в репозитории
и нажмите «Сканировать».
Ожидается два сертификата — Иванова и Петрова — без ошибок. Контейнеры `.p12`
и `README.md` будут пропущены. Примеры организаторов не изменяются.

Для проверки удалённого ПК выберите вкладку «Компьютеры», нажмите «Добавить»,
введите IPv4, логин, пароль и при желании название. После сохранения начнётся подключение.
Отметьте нужные ПК, проверьте пути в выбранной конфигурации и нажмите «Сканировать».
После перезапуска те же отмеченные ПК подключатся автоматически; сканирование
запускается отдельной кнопкой.
В режиме «Папка» также можно ввести UNC-путь, например `\\192.168.56.101\C$\Certs`. Используются права текущей
учётной записи Windows; приложение не открывает общий доступ и не меняет настройки
целевого компьютера. Доступ к SMB и административной папке должен быть подготовлен
администратором. Открытый порт 445 не подтверждает наличие доступа к `C$`/`D$`:
права проверяет Windows при чтении самих папок. Приложение не меняет службы,
брандмауэр и политики учётных записей. Новую авторизацию и автоматическое подключение
нужно отдельно проверить с Windows 10 в сети; автоматические сетевые сценарии используют тестовый адаптер.
`connectionTimeoutSeconds` (1–60) ограничивает только установление TCP-соединения;
последующие SMB-операции зависят от системных таймаутов Windows.
Кнопка отмены останавливает дальнейший обход, но не прерывает уже начатый блокирующий
системный вызов SMB: его завершение зависит от сетевых таймаутов Windows.

Для переноса программы сохраняйте рядом `.exe`, `Telecom.Core.dll`,
`Telecom.App.exe.config` и `scan.config.template.xml` из папки сборки. Установка SDK на целевой ПК администратора
не нужна; на сканируемые ПК наше приложение не копируется.

## Проверки

```powershell
dotnet build Telecom.sln -c Release
& .\tests\Telecom.Tests\bin\Release\net45\Telecom.Tests.exe
```

Это небольшой исполняемый набор проверок без дополнительного тестового фреймворка.
Код возврата `0` означает успех. Образцы находятся автоматически по папке `Test_sert`
в родительских каталогах; при необходимости путь можно передать первым аргументом.

Проверяются исходные сертификаты организаторов, текстовые и сериализованные форматы,
повреждённые данные, отказ от чтения ключевых контейнеров, продолжение обхода после
ошибки, отмена, ограничение размера и параллельное логирование. Отказ доступа и ссылка
моделируются адаптером без изменения ACL, служб Windows или хранилища сертификатов.
Дополнительно проверяются создание и перенос пользовательской конфигурации, XML и его ошибки, построение UNC-путей, маски профилей,
диски C:/D:, частичный сбор, сетевые ошибки, закрытая административная папка,
поиск КриптоПро по двум путям и нормализация ProductVersion.
Проверки списка ПК охватывают раздельное сохранение IPv4 и названий, строгую проверку IPv4,
перенос прежних записей, сохранение галочек, дубли, повреждённый XML,
автоподключение после открытия окна, пропуск невыбранного ПК и продолжение после
недоступного ПК. Проверяются обязательность учётных данных для подключения и чтение
сертификатов после авторизации с сохранённой учёткой ПК.
Проверки дополнительных путей охватывают хранение, загрузку версий 1 и 2, проверку ввода,
объединение путей отдельно для каждого ПК, перекрытие папок и продолжение после отказа доступа.
Проверки диспетчера учётных данных создают только собственные записи со случайными
идентификаторами и вымышленными паролями, обновляют их и удаляют в `finally`.
Настоящие учётки и сетевые соединения пользователя эти проверки не читают и не изменяют.
Все временные данные создаются в системной временной папке и удаляются после проверок.

Проверки записи в MSSQL (создание таблицы, первое внесение, обновление без дублей) выполняются,
если задана переменная окружения `TELECOM_TEST_SQL` со строкой подключения к отдельной базе,
имя которой оканчивается на `Tests`. Они пересоздают в ней таблицу `dbo.Certificates`.
Они также создают и удаляют на том же сервере базу `TelecomCreateTests` и временную учётную запись
`telecom_restricted_test`, поэтому учётной записи проверок нужны права администратора сервера.
Без переменной эти проверки пропускаются с пометкой `SKIP`.
